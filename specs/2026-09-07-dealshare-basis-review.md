# 딜지분 계산 기준과 공개 딜컷 비교

확인일: 2026-09-07. 대상: `/딜지분`·`/딜컷`의 공개 딜컷 기준 전환. 기존 지원 13개 난이도·26관문을 유지한다.

## 1. 확인된 차이

전환 전 피해량 9,878억을 입력했을 때 체력 기준 계산과 비교 화면의 잔혈 기준이 달랐다. 아래 '기존' 수치는 전환 전 동작이다.

| 관문 | 기존 보스 체력 | 기존 잔혈 20% 컷 | 로아뷰 공개 잔혈 컷 | 기존 / 공개 컷 부족량 |
|---|---:|---:|---:|---:|
| 나메 1관 | 4,951,627,226,525 | 약 9,903.25억 | 9,883억 | 25억 / 5억 |
| 나메 2관 | 5,605,114,847,754 | 약 11,210.23억 | 11,188억 | 1,332억 / 1,310억 |

기존 지분은 19.948998% / 17.623189%이며 화면에는 19.9% / 17.6%로 표시했다. 공개 컷에서 분모를 역산하면 비교 화면의 20.0% / 17.7%와 부족량이 재현된다. 11,000억 입력의 비교 화면 22.3% / 19.7%, 2관 부족 188억도 같은 공개 컷으로 재현된다. 비교 봇의 내부 구현·직접 사용 출처는 확인하지 않았다.

약 0.2%는 지분의 0.2%p 차이가 아니라 컷에서 역산한 분모와 현재 체력 사이의 상대 차이다. 분모에 0.998을 곱해도 이 두 예시가 재현되지만 표시값이 반올림되어 있어 정확한 계수를 유일하게 정할 수 없다. 지분 표시만으로는 올림 방식도 구별할 수 없지만 부족량까지 비교하면 단순 표시 반올림만의 차이는 아니다.

## 2. 출처와 확인 범위

- [로펙 기여도 계산기](https://lopec.kr/tool/mvp): 2026-09-07 화면과 페이지가 참조한 계산 번들을 대조했다. 벨가르딘 나메 체력 두 값이 저장 자료와 일치하며 기본 분모는 보스 체력에서 선택된 택틱 피해를 뺀 값이다. 해당 두 관문의 기본 택틱 피해는 0이다. 서포터 입력에 따른 별도 역산 모드는 이번 기본 딜러 계산과 구분한다.
- [로아뷰 벨가르딘 표](https://loaviewer.github.io/dps/belgardin.html)와 연결된 [공개 데이터 시트](https://docs.google.com/spreadsheets/d/1v4gfG-Lr0iFmiP0PXtVTsijdMziekQaZ-wBTWrobncY/edit#gid=0): 나메 20% 행의 두 값은 9,883억·11,188억이다. 내보낸 시트의 해당 셀은 수식이 없는 값이므로 산출 과정을 복원할 수 없다.
- [표 작성자의 원글](https://www.inven.co.kr/board/lostark/4821/108048): 벨가르딘 표 이미지도 같은 값을 표시한다. 본문은 변수 한 개를 적용했다고만 적으며 그 내용을 정의하지 않는다.
- 원 작성자의 2025-09-12 댓글 2354879·2354882는 체력·실드 합계에서 에스더와 서포터 직접 피해를 차감하고 실제 파티 결과와 대조하는 일반 산출 방식을 설명한다. 벨가르딘 추가 이전의 설명이며 0.2% 수치의 직접 근거가 아니다. 2026-08-09 댓글 2377482의 예시는 서포터 피해 부호가 앞선 설명과 상충한다. 공개 댓글 154개를 확인했지만 벨가르딘의 고정 0.2% 차감이나 변수 한 개의 정체를 확정할 근거는 찾지 못했다.

서포터 피해 차감이 공개 표의 산출 요소라는 근거는 있으므로 이를 원인 후보에서 배제하지 않는다. 반대로 이번 약 0.2% 전부가 서포터 피해라고 단정하지도 않는다. 실측 오차·마감 체력·안전 여유 중 하나를 가장 유력하다고 정할 자료도 없다. 공개 컷에서 역산한 값은 보스 체력 자체와 동일하게 취급하지 않는다.

## 3. 확정한 계산 기준

처음에는 기존 계산에 출처 안내만 추가했으나, 비교 설명 후 공개 딜컷 기준으로 바꾸기로 결정했다. 현재 구현은 다음 규칙을 따른다.

- `src/data/raid-cuts.js`에 공개 컷과 확인일을 저장한다. 강투·1인분·잔혈은 공개된 절대 피해량을 각각 사용하며 한 컷에서 나머지 컷을 비례 계산하지 않는다. 아래의 4막·종막 1인분만 공개 사이트의 파생 계산을 따른다.
- 지분의 기준 피해량은 `공개 잔혈 컷 / 잔혈 비율`이다. 잔혈 비율은 4인 40%, 8인 20%다. `내 피해량 / 기준 피해량`을 지분으로 표시한다. 역산한 기준은 실제 보스 체력이나 실제 공대 총 피해량이라는 뜻이 아니다.
- 칭호와 각 컷의 달성·부족량은 내 피해량과 공개 절대 컷을 직접 비교한다. 표 자체의 반올림 때문에 지분 비율과 절대 컷이 정확히 비례하지 않아도 절대 컷을 우선한다. 9,878억은 나메 1관에서 20.0%로 보이지만 공개 잔혈 컷 9,883억보다 5억 부족하다.
- 기존 `raidhp.js`의 보스 이름·관문·인원·제한시간은 유지한다. 원본 체력·택틱 수치는 참고 자료로 보존하지만 현재 계산에 사용하지 않는다. 택틱이나 서포터 피해를 다시 차감하지 않으며 고정 0.998 보정도 없다.
- 사용자 지정 시간은 DPS에만 적용한다. 지분·절대 컷·판정에는 영향을 주지 않는다. 슬래시 옵션·텍스트 별칭·관문 선택·현재 지원 레이드는 그대로다.
- 지분은 소수 1자리, 피해량은 억 단위로 반올림해 표시한다. 판정은 표시 전 피해량으로 한다. 응답·난이도 목록·도움말·README·홈페이지에 공개 딜컷 기준과 예상치임을 알린다.

### 자료 선택과 추적

게임 공식 기준을 의미하지 않는 공개 커뮤니티 자료이며, 실시간 조회 없이 2026-09-07 확인 사본을 사용한다. 상세표가 있으면 상세표를 우선하고, 없는 4막·종막은 [공개 사이트 코드](https://loaviewer.github.io/js/index.js)의 현행 간편보기 값을 따른다.

4막·종막의 실제 원본은 JS `simpleData` 상수다. 아래 AE열은 같은 값이 있는 대조 셀이며 사이트가 이 셀을 읽는다는 뜻은 아니다. 사본은 2026-09-07 22:06 KST 수집, 22:50 KST 재조회에서도 동일했다. CSV SHA256은 `033baed46b95fabdd3ea9fc41a3f7c3807ca825f49daf9271b41d684a7b13d89`, JS SHA256은 `b0e70a0ff0ab9afd438182f1f906ef1b55d1e83152553e649052c857e347f622`다. 후속 갱신은 두 원문과 해시를 다시 대조하고, 바뀐 관문·표시 비율·파생식을 검증한 뒤 확인일을 갱신한다.

4막·종막에는 독립 1인분 셀이 없다. 공개 사이트의 `parseSimpleRangeParts`와 같이 억 단위에서 `Math.round((잔혈 / 0.2 / 6) / 10) * 10`을 적용한다. 저장 자료의 `oneDerived`와 응답 안내로 직접값과 구분한다. 독립 공개 컷은 70개, 파생 1인분은 8개로 총 78개다.

자료 내부 불일치는 다음처럼 처리한다.

- 성당 2단계의 오른쪽 간편 요약은 1관 2370~3160억·2관 2300~3060억이지만 상세표는 강투/1인분/잔혈이 2161/2377/2882억·2089/2298/2786억이다. 현행 사이트의 성당 2단계 간편 요약은 상세표와 일치한다. 다른 성당·세르카에도 요약 반올림 및 1/3과 33% 차이가 있다. 모두 상세표를 우선한다.
- 종막 하드의 일부 레벨별 요약(1730·1740)에는 2370~3170억·4200~5625억이 남아 있다. 현행 사이트가 모든 레벨에서 선택하는 1750 요약의 2025~2700억·3375~4490억을 적용한다. 독립 1인분은 없으므로 2250억·3740억으로 파생한다. 서로 다른 표를 섞거나 평균하지 않는다.
- 이 선택이 실전의 정확한 피해량을 입증하지는 않는다. 공개 표의 작성 가정·파티 구성·택틱·자료 갱신 상태에 따라 실제 MVP와 차이가 날 수 있다. 0.2%의 정확한 구성은 여전히 미확정이다.

## 4. 검증 및 배포 전제

공개 셀·사이트 선택 규칙과 26관문 78개 컷을 대조한다. 실제 명령 실행과 카톡 브리지에서 두 비교 입력, 컷 직전·정확히 일치·직후, 기본 택틱이 있던 관문, 사용자 지정 시간, 난이도 목록, 별칭·미지원·잘못된 입력과 도움말 전체 보기를 검증한다. 조사 자료와 검증 스크립트는 임시 폴더에 보존한다.

명령 정의·환경변수·의존성·상태 파일·폰 스크립트 변경은 없다. 명령 재등록이 필요하지 않다. 이 정정의 머지·배포는 별도 출시 단계다.
