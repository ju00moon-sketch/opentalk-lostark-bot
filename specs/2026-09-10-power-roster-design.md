# 전투력 이미지 제거와 원정대 부캐 전투력

## 사용자 흐름

- `/전투력 [닉네임]`의 캐릭터 이미지를 디스코드·카카오톡에서 제거한다.
- 닉네임 생략 시 등록 캐릭터와 기존 닉네임 대체 규칙을 유지한다. 명령 정의·옵션·별칭을 변경하지 않는다.
- 조회한 캐릭터의 전투력·아이템 레벨·공격력·최대 생명력·전투 특성은 기존 문구와 수치를 유지한다.
- 카카오 오픈채팅에서는 본문에 기존 기본정보를 보내고, 기존 전체 보기 링크에 기본정보와 부캐 전투력을 함께 담는다. 페이지는 그림 없이 텍스트를 보여 주며 30분 후 만료된다.
- 부캐는 `닉네임 · 직업 · 전투력 1,234.5` 한 줄씩 표시한다. 기존 `/원정대`와 같이 계정의 모든 서버를 포함하되 조회한 캐릭터와 중복 닉네임은 제외한다. 본캐와 서버가 다르면 행 끝에 `(서버명)`을 붙인다.
- 전투력이 높은 순으로 정렬하고 같은 값이면 닉네임순으로 표시한다. 프로필은 조회됐지만 전투력 값이 없으면 하단에 `전투력 -`로 표시한다. 조회 실패한 캐릭터는 `조회 불가`로 구별한다. 부캐가 없으면 다른 캐릭터가 없다는 안내를 표시한다.

## 조회 계약

`src/power-roster.js`는 `createPowerService()`와 기본 인스턴스의 `getPowerProfile(name)`, `getPowerRoster(profile)`를 제공한다.

- `getPowerProfile(name)`은 공식 프로필 응답 또는 `null`을 반환한다. 요청 실패는 기존 HTTP 오류 안내와 동일한 오류를 던진다.
- `getPowerRoster(profile)`은 `{ status, characters, total, failed }`를 반환한다.
- `characters`의 행은 `{ name, className, serverName, combatPower, state }`이다. `combatPower`는 0 이상의 유한한 숫자이며 조회 불가·누락·잘못된 형식은 `null`이다. `state`는 숫자 전투력이 있으면 `available`, 정상 프로필에 숫자 전투력이 없으면 `missing`, HTTP 실패·시간 초과·프로필 없음 또는 잘못된 프로필 응답이면 `unavailable`이다.
- `status`는 전부 성공 또는 부캐 없음이면 `ok`, 일부 실패면 `partial`, 전부 실패 또는 목록 조회 실패면 `unavailable`이다.
- `total`은 본캐와 중복을 제외한 부캐 수이다. 목록을 얻지 못한 경우에만 `null`이다. `failed`는 프로필 조회에 실패한 부캐 수이며 정상 프로필에 전투력 값이 없는 캐릭터는 포함하지 않는다.
- 부캐 전투력은 `/armories/characters/{characterName}/profiles`의 실제 `CombatPower`를 사용한다. 아이템 레벨로 추정하지 않는다.
- `/characters/{characterName}/siblings`는 닉네임·서버·직업·레벨만 제공한다. 따라서 부캐 N개를 처음 조회하면 본캐 프로필 포함 최대 N+2회의 공식 API 요청이 필요하다.

공식 응답 정의: [원정대 목록](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/characters), [캐릭터 프로필](https://developer-lostark.game.onstove.com/swagger-doc/endpoints/armories).

## 시간·동시성·실패 처리

- 전용 모듈에서 공식 API HTTP 요청은 동시에 최대 3개만 실행한다. 다른 명령의 공용 API 모듈은 변경하지 않는다.
- 요청별 제한 3초는 대기열 대기·연결·응답 본문 수신을 모두 포함한다. 부캐 목록과 부캐 프로필 전체 조회의 제한은 10초이다. 본캐 프로필은 별도 요청 제한 3초를 적용한다.
- 취소는 `AbortSignal`을 HTTP 요청까지 전달한다. 취소된 대기열 항목은 제거하고, 원정대 전체 제한이 지나면 새 부캐 요청을 시작하지 않는다. 시작하지 못한 부캐도 조회 불가 행으로 남긴다.
- 같은 API 요청과 같은 기준 캐릭터의 원정대 요청은 진행 중 작업을 공유한다. 한 원정대 요청이 종료돼도 다른 조회가 사용하는 프로필 요청은 유지하고, 이용자가 모두 종료되면 요청을 취소한다.
- 검증된 성공 API 결과와 전체 성공 원정대 결과만 60초간 보관한다. 정상 프로필에 전투력 값이 없는 경우도 성공 결과다. 각 캐시는 최대 100항목이며 진행 중 요청도 종류별 최대 100개로 제한한다. 부분 실패·전체 실패·잘못된 목록/프로필 응답은 성공 결과로 캐시하지 않는다.
- 공식 API는 분당 100회 제한이 있다. 병렬 수와 캐시는 요청을 줄이지만 다른 명령을 합친 전체 사용량 제한을 보장하지 않으므로 429도 명시적인 조회 실패로 처리한다.
- 부캐 조회의 일부 또는 전체가 실패해도 본캐 기본정보는 유지한다. 전체 보기에서 조회 실패 또는 시간 초과와 실패 개수를 안내한다.

## 적용 범위와 검증

- 카카오 `kakaoFull` 계약은 오픈채팅 브리지에서 사용한다. 오픈빌더 스킬 JSON에는 추가 전문이 포함되지 않는다.
- 디스코드는 이미지 제거와 본캐 기본정보 유지까지 적용한다. 더보기 플랫폼 확인 전 별도 디스코드 버튼은 추가하지 않는다.
- 공용 API·카카오 렌더러·핸들러·버튼·폰 스크립트·등록 정의·환경변수·저장 형식은 변경하지 않는다. 재등록과 데이터 이전은 필요 없다.
- 전용 합성 검사로 서버 범위·본캐 제외·수치 정렬·0부캐·부분/전체 실패·캐시/동시 공유·대기열 취소·본문 수신 시간 초과를 확인한다.
- 실제 카카오 명령 핸들러와 디스코드 대역 인터랙션에서 최종 응답을 확인한다. 긴 전문은 모든 행이 보관되고 채팅 본문은 1,500자 이하인지 확인한다. 이는 실채팅 발송이나 실제 휴대전화 도착 검증을 대신하지 않는다.
