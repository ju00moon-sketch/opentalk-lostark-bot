# 카카오톡 전용 출석 체크 `/출첵` — 설계 (2026-09-07)

사용자 요청: ".ㅊㅊ 커맨드 넣어줘 ㅊㅊ도 입력먹게 포인트는 1~3p랜덤이고 하루에 한번 명령어먹게". 하루 한 번 출석해 1~3P를 무작위로 받고 누적 포인트를 보는 명령이다. `.ㅊㅊ`뿐 아니라 접두사 없는 `ㅊㅊ`도 받는다.

**최종 플랫폼 결정(2026-09-07)**: 출첵은 카카오톡 전용이다. 디스코드 슬래시·텍스트 목록에서는 제외하며 저장 코어는 그대로 유지한다.

## 1. 목표와 비목표

- 목표: 카카오톡 `/출첵`·`ㅊㅊ`·`.ㅊㅊ`로 하루 한 번(한국 시간 자정 기준) 1~3P를 무작위로 받고, 누적 포인트와 출석 횟수를 본다. 같은 날 다시 하면 이미 출석했다고 안내한다.
- 비목표: 포인트 랭킹·교환·차감·관리자 조정, 연속 출석 보너스, 디스코드와 카톡 계정 통합, 채널·방별 분리, 자정 알림. 요청되면 별도 작업.

## 2. 규칙과 저장

- 하루 기준: 한국 시간(UTC+9) 달력 날짜. 23:59에 출석하고 00:00에 다시 출석할 수 있다.
- 포인트: 출석마다 1·2·3 중 하나를 같은 확률로 준다(`Math.random`, 테스트는 주입).
- 사용자 식별: 카톡 브리지가 넘기는 `kakao:oc:<닉>`(등록 저장소 `user-links.json`과 같은 키). 카톡 닉을 바꾸면 새 사람으로 센다(브리지 한계, 등록 명령과 동일).
- 저장: 루트 `attendance.json` `{ "<userId>": { "points": 누적, "count": 횟수, "last": "YYYY-MM-DD" } }`. `json-store.js`의 `readJson`(깨진 파일이면 저장 거부)·`writeJsonAtomic`(임시 파일 → 교체, .bak, 0600)을 그대로 쓴다. 배포가 `src/`만 교체해도 유지되도록 다른 상태 파일과 같은 위치, `.gitignore`에 추가.
- 동시성: 읽기·판정·쓰기가 한 동기 구간이라 같은 프로세스에서 겹치지 않는다. 파일이 깨져 있으면 저장하지 않고 실패 문구를 낸다(등록 저장소와 같은 정책).
- 구조 검증(기술 검토 P2-1 반영): 파싱은 되지만 루트가 객체가 아니거나(배열·null) 항목의 `points`·`count`가 0 이상 정수가 아니거나 `last`가 `YYYY-MM-DD`/null이 아니면 손상으로 보고 `CorruptStoreError`를 던진다. 저장·백업을 하지 않아 원본과 `.bak`이 보존된다(배열 위에 저장하면 기록이 사라지고 `'5' + 2`는 `'52'`가 되는 문제 차단).

## 3. 입력과 출력

- 카톡: `/출첵`, `.출첵`, `/ㅊㅊ`, `.ㅊㅊ`, **접두사 없는 `ㅊㅊ`**. `kakao/handler.js`의 `bareAliases`와 폰 필터가 함께 허용한다. 디스코드에서는 슬래시 `/출첵`·`/ㅊㅊ`를 등록하지 않고 `ㅊㅊ`·`.ㅊㅊ`도 처리하지 않는다.
- 출석 성공: `✅ 블레상돈님 출석 완료! +2P · 누적 5P · 3번째 출석`
- 같은 날 재시도: `블레상돈님은 오늘 이미 출석했어요 · 누적 5P · 내일 00:00(한국 시간)부터 다시 할 수 있어요`
- 저장 실패: `출석 기록을 저장하지 못했어요. 잠시 후 다시 시도해 주세요`
- 이름은 카톡 방 닉네임이며 평문 한 줄로 답한다. 별명이 답장에 들어가므로 성공·이미 출석 답장은 `allowedMentions: { parse: [] }`를 유지한다(기술 검토 P2-2 반영).

## 4. 구조와 분담

제품 단독 구현(기존 명령 + 기존 저장 모듈). 새 상태 파일 저장이라 기술 교차 검토 대상.

- 신규 `src/attendance.js`: `kstDate(ms)`, `rollPoints(random)`, `checkIn(userId, { now, random, storePath })`.
- 신규 `src/commands/attendance.js`: `/출첵`, `createExecute({ checkIn, now })`, 문구.
- `src/commands/index.js`의 `kakaoCommands`에만 포함한다. `src/text-commands.js` 별칭 `ㅊㅊ`, `src/kakao/handler.js`의 `bareAliases`, 폰 필터와 카톡 도움말에 반영한다. 디스코드 기본 명령 58개에는 출첵을 포함하지 않으며 별칭 슬래시도 등록하지 않는다.

## 5. 인터페이스 계약

- `kstDate(ms)` → `'2026-09-07'`.
- `rollPoints(random = Math.random)` → 1·2·3.
- `checkIn(userId, { now = Date.now, random = Math.random, storePath } = {})` → 성공 `{ status: 'done', gained, total, count, date }`, 같은 날 `{ status: 'already', total, count, date }`. 파일이 깨져 있으면 `CorruptStoreError`를 던진다(저장하지 않음).
- 명령 `createExecute({ checkIn, now })`.

## 6. 검증 기준

1. `kstDate` 자정 경계(14:59:59Z = 23:59:59 KST, 15:00:00Z = 다음 날 00:00 KST).
2. 첫 출석 `done`·주입한 random에 따른 1/3P, 파일 저장 내용, 같은 날 `already`(포인트 불변), 다음 날 `done`·누적·횟수, 사용자별 분리.
3. 깨진 파일은 예외·파일 불변. 저장 예외 시 명령은 실패 문구.
4. 카톡 명령 문구(성공·이미 출석·실패), 닉네임 표시.
5. 등록: 디스코드 목록에 출첵·ㅊㅊ가 없고 텍스트 입력도 미처리. 카톡 `/출첵`·`.출첵`·`/ㅊㅊ`·`.ㅊㅊ`·접두사 없는 `ㅊㅊ`와 폰 필터를 확인한다.
6. 실제 브리지 경로(`handleBridgeMessage`)로 카톡 `ㅊㅊ` 1회 → 성공, 2회 → 이미 출석(임시 저장 파일).

> 아래 검증 기록과 정의 수는 플랫폼·등록 정책 변경 전의 이력이다. 현재 입력·등록 계약은 위 검증 기준과 아래 배포 전제를 따른다.

## 7. 배포 전제·위험·결정

- 출첵 자체는 카톡 전용이라 슬래시 추가 등록이 없다. 이번 플랫폼 정책 적용 시 디스코드 목록은 기본 58개로 재등록한다. 새 상태 파일 `attendance.json`은 첫 출석이 서버 루트에 만든다(gitignore). 새 환경변수·의존성 없음. 폰 스크립트는 `scripts/messengerbot-r.js`를 사용자가 교체해야 접두사 없는 `ㅊㅊ`가 방에서 전달된다(교체 전에도 `.ㅊㅊ`·`/ㅊㅊ`는 동작).
- `feat/bracelet-search`와 index.js·text-commands.js·help·README·index.html 인접 행이 겹쳐 통합 순서에 따라 충돌 확인.
- 결정: 한국 시간 자정 기준, 1~3P 균등, 계정 통합 없음, 랭킹 없음(사용자 요청 범위).
