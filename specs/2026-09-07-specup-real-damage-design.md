# `/스펙업` 실질 딜 상승률 전환 — 설계 (2026-09-07)

사용자 요청: 스펙업 효율을 로펙 점수가 아니라 실질 딜 상승으로 보여 달라. 보석은 직업별 스킬 딜 지분을, 작열은 그 스킬의 쿨감 효율을 따라야 한다. 참고 사이트는 로아업(loaup.com). 승인: "ㅇㅇ 뭐 하면 되지".

## 1. 목표와 비목표

- 목표: `/스펙업` 후보마다 **딜 상승률(%)** 과 **10만 골드당 딜 상승률**을 보여 주고 그 기준으로 정렬한다. 보석(겁화·작열) 후보는 우리 데이터(직업·빌드별 스킬 딜 비중)와 우리 계산식으로 평가하고, 나머지 후보는 로펙 점수의 비율을 그대로 딜 상승률로 쓴다.
- 비목표: 로펙 엔진 교체, 자체 전체 DPS 시뮬레이터, 로아업 크롤링·API 이용(약관 6조 금지 — 손으로 참고만), 완갑 모델 수정(별도 조사), 서포터 효율, 아바타·아크그리드 후보 추가.

## 2. 근거 (2026-09-07 대조)

블레상돈으로 우리 `/스펙업`의 `점수 상승 ÷ 현재 점수`와 로아업 실효율을 비교했다.

- 강화·장신구·무기는 5~10% 안에서 같다 → 로펙 점수는 딜 지수이며 비율이 곧 딜 상승률이다. 이 부분은 계산식이 필요 없다.
- 보석만 다르다. 로펙은 이 캐릭터가 쓰지 않는 페이탈 웨이브에 가장 큰 비중을 주고, 로아업은 빌드에 맞춰 블레이드 버스트 26 · 소울 앱소버 18 · 보이드 스트라이크 14 · 트윈 쉐도우 10 · 터닝 슬래쉬 7, 안 쓰는 스킬 0으로 잡는다. 로아업의 겁화 값은 `비중 × ((1+D_다음)/(1+D_현재) − 1)`로 재현된다(블버 26% × 4%p 차 ≈ 0.76~0.79%).
- 로펙 자체도 "보석 점수는 스킬별 딜 지분에 맞춰 제공"한다고 밝히지만(자료 없는 직업은 로그스케일 평균) 빌드·장착 스킬 반영이 약하다.
- 로아업: 공개 API 없음, 비브라우저 UA 403, robots `Content-Signal: search=yes,ai-train=no,use=reference`, 약관 6조가 자동화·크롤링·우회 접근을 금지. 따라서 **손으로 읽어 표를 만드는 참고 용도만** 허용한다. 완갑 차이(2.379% 대 0.447%)는 원인 미확인 — 이번 범위 밖, 로펙 값 유지.

## 3. 사용자 흐름과 출력

입력·별칭·캐시·카톡 경로는 현행 그대로. 바뀌는 것은 수치와 정렬뿐이다.

디스코드 한 줄(상위 10):
```
1. 보석 · 블레이드 버스트 · 7레벨 겁화 → 8레벨 겁화  +0.79% · 361,000G · 0.22%/10만G
2. 악세 · 반지 2 · 치적 [하] / 치피 [중] → 치적 [중] / 치피 [중]  +0.38% · 13,700G · 2.74%/10만G
```
카톡 항목(상위 5, 전체 보기는 모든 후보):
```
1위 · 반지 2 교체
치적 하 → 중 · 치피 중 유지

예상 비용: 13,700골드
딜 상승: +0.38%
투자 효율: 2.74% / 10만 골드
```
- 정렬 = 10만 골드당 딜 상승률 내림차순(현행 '점수/10만G'와 같은 위치). 무료·고정 비용 행 규칙은 현행 유지.
- 헤더 `블레이드 (1,775.00) · 현재 로펙 5,115.8`은 유지(점수는 기준값으로만).
- 푸터 첫 항목: 보석 행에 모델이 하나라도 적용됐으면 `딜 상승률은 로펙 점수 비율, 보석은 스킬 딜 비중 기준(자료 2026-09-07)`, 아니면 `딜 상승률은 로펙 점수 비율`. 보석 행 중 로펙 값으로 대체된 것이 있으면 이어서 `일부 보석은 로펙 점수 비율`(모델 적용 행도 있을 때) 또는 `보석은 로펙 점수 비율(딜 비중 모델 미적용)`(전부 대체)을 넣는다. 대체 사유(직업·빌드 자료 없음, 공식 조회 실패, 3·4레벨 보석 수치 미확인)는 여러 가지이므로 푸터에서 원인을 단정하지 않는다(기술 검토 P2, 2026-09-07). 항목 안에 ` · `를 쓰지 않는다(카톡이 ` · `로 줄을 나눈다). 다른 푸터 항목(시세 시각·로펙 시세·스톤/카르마 고정 비용·페온·비용 미확인)은 그대로.
- 전체 보기의 점수 줄: 로펙 비율 행은 `변경 후 점수: N점`(로펙 순위 참고용), 모델 적용 행은 `모델 환산 점수: N점`(코어가 `baseScore × (1 + 딜 상승률)`로 환산한 값이라 로펙 점수가 아님 — 기술 검토 P2). 딜 상승률과 투자 효율은 소수 2자리(`+0.98%`, `0.27% / 10만 골드`), 무료 행은 `무료 · —`.

### 5-1. `src/data/skill-shares.js` (기획)

```js
export const DATA_DATE = '2026-09-07';
export const SKILL_SHARES = {
  '블레이드': [
    { build: '잔재', detect: { tree: '깨달음', node: '잔재된 기운' }, cooldownUse: 1,
      shares: { '블레이드 버스트': 26, '소울 앱소버': 18, '보이드 스트라이크': 14, '트윈 쉐도우': 10, '터닝 슬래쉬': 7, '페이탈 웨이브': 0, '블리츠 러시': 0, '마엘스톰': 0 },
      source: '로아업 블레상돈 2026-09-07' },
  ],
};
// nodeNames = ArkPassive.Effects[].Description에서 '깨달음 1티어 ' 같은 접두사를 뗀 노드 이름 배열(crit.js의 nodeName과 같은 규칙).
export function findBuild(className, nodeNames): { build, cooldownUse, shares, source } | null
```
- `shares` 값은 전체 피해 중 그 스킬의 몫(%). 합은 100 이하이며 100일 필요 없다(보석을 낄 수 있는 스킬만 적는다). 스킬 이름은 공식 API `ArmorySkills[].Name`·보석 `Effects.Skills[].Name`과 글자 그대로 같아야 한다.
- 명시적 `0`은 "이 빌드에서 안 쓴다"이고, 표에 없는 스킬은 "모른다"(코어가 로펙 값으로 대체).
- `detect`는 아크패시브 노드 이름 하나로 판별한다. 여러 빌드가 있으면 배열에 나열하고 첫 일치를 쓴다. 일치가 없으면 `null`. 공식 API의 노드 설명은 `깨달음 2티어 잔재된 기운 Lv.3`처럼 오므로 `findBuild`가 끝의 ` Lv.N`을 떼고 비교한다(2026-09-07 블레상돈 실조회로 확인).
- `cooldownUse`는 작열의 쿨감 활용 계수(0~1, 기본 1 = 쿨타임 완전 소화, 로아업과 같음. 로펙은 0.9). 빌드별로 낮출 수 있다.

### 5-2. `src/gem-model.js` (기술)

```js
// 한 보석 변경의 딜 상승률(%). 계산 불가(직업·빌드·스킬 자료 없음, 보석 종류 미지)는 null과 이유.
export function estimateGemGain({
  className, nodeNames,                   // 문자열, 문자열 배열 → 내부에서 findBuild
  skills,                                 // ArmorySkills: [{ Name, Level, Tripods: [{ IsSelected }] }] — Level ≤ 1이고 선택 트포 없음 = 배우지 않은 스킬
```

- 단위: `gainPercent`는 % 값(0.79 = 0.79%). `parts.skill`은 스킬 피해·쿨감 부분, `parts.attack`은 기본 공격력 증가 부분(둘 다 %).
- 순수 함수, 네트워크 없음, 예외를 던지지 않는다(잘못된 입력도 `null`+이유).

### 5-3. `src/data/gems.js` (기술)

현행 보석은 **광휘의 보석**(전설, 티어 4) 하나이며 보석마다 스킬 효과를 `피해 N% 증가` 또는 `재사용 대기시간 N% 감소` 중 하나로 조율하고, 추가 효과로 `기본 공격력 N% 증가`가 붙는다(2026-09-07 블레상돈 실조회: 7레벨 = 피해 32.00% · 쿨감 18.00% · 기본 공격력 0.60%, `Effects.Description` = `기본 공격력 총합 : 6.60%` = 11개 합). 표는 레벨 1~10의 `피해 %`·`쿨감 %`·`기본 공격력 %` 세 열이다. 값은 공식 전투정보실 보석 툴팁(`ArmoryGem.Gems[].Tooltip`, `Effects.Skills[].Description`·`Option`)으로 검증하고 파일에 확인 날짜를 적는다. 코어는 캐릭터가 실제로 낀 레벨은 툴팁 값을, 없는 레벨은 이 표를 쓴다. 로펙 행 라벨(`7레벨 겁화`·`7레벨 작열`)은 각각 피해·쿨감으로 읽는다.

### 5-4. `src/lopec-sim.js` 변경 (기술)

- 보석 행(`kind === '보석'`)에 `gem: { skill, type, from, to }`를 붙인다(현재 `cells.mainInfo`가 스킬 이름, `currentState`/`nextState`가 `7레벨 겁화` 형식).
- `getSpecupGuide()` 반환 행마다 `gainPercent`(%)와 `per100k`(= gainPercent ÷ 비용 × 100,000, 무료·고정은 현행 규칙)를 넣는다. 비보석 행은 `(finalScore − baseScore) ÷ baseScore × 100`. 보석 행은 `estimateGemGain` 결과를 쓰고, `null`이면 로펙 비율로 두고 `gainSource: 'lopec'`를 표시한다(그 외 `gainSource: 'model'`). `finalScore`·정렬은 `gainPercent` 기준으로 재계산해 표시 계층이 한 기준만 보게 한다.
- 공식 API 조회: `getArmoryPart(name, 'combat-skills')`·`'gems'`·`'arkpassive'`·프로필의 직업명 — 기존 5분 캐시 규칙과 시간 제한을 따르고, 조회 실패 시 보석 행은 로펙 비율로 대체(전체 실패 아님).

## 6. 계산 규칙 (코어)

기호: 스킬 s의 비중 `w_s`(0~1), 겁화 피해 증가 `D_L`, 작열 쿨감 `C_L`, 기본 공격력 증가 `A_L`(각각 레벨 L).

1. 스킬 사용 여부: `skills`(전투 스킬 목록)에 이름이 같은 스킬이 **있고** `Level ≤ 1`이며 선택 트포가 없으면 `w_s = 0`. 목록에 아예 없는 스킬(블레이드 버스트 같은 정체성 스킬은 `combat-skills`에 오지 않는다)은 사용 중으로 본다. 표에 없는 스킬은 계산 불가(`null`, 이유 `스킬 자료 없음`).
2. 피해(겁화) a→b: `skill = w_s × ((1 + D_b) / (1 + D_a) − 1)`.
3. 쿨감(작열) a→b: `skill = w_s × cooldownUse × ((1 − C_a) / (1 − C_b) − 1)`. 쿨타임을 다 돌린다는 가정이며 시전 시간·백어택 등은 무시한다(로아업 설명과 같은 근사).
4. 기본 공격력: 광휘 보석의 `기본 공격력 N% 증가`는 보석마다 **합산**된다(`Effects.Description`의 총합과 일치). `A_sum_before`·`A_sum_after`를 장착 보석 전체에서 구해 `attack = (1 + A_sum_after) / (1 + A_sum_before) − 1`. 다른 공격력 증가 원천과의 합산 방식은 근사로 무시한다(오차 1%p 미만).
5. `gainPercent = (skill + attack) × 100`. 스킬 부분이 0이어도 공격력 부분은 남을 수 있다(로아업 "클릭하여 스킬+공증 표시"와 같은 구조).
6. 여러 단계(7→9, 7→10)도 같은 식으로 한 번에 계산한다.
7. 대체(보석 행이 로펙 점수 비율로 돌아가는 조건, 구현 `1133b08` 기준): (a) 직업이 표에 없음 → 공식 API를 조회하지 않고 전부 대체, (b) 빌드 미판별, (c) 공식 `combat-skills`·`gems`·`arkpassive` 중 하나라도 실패·형식 불일치·공격력 총합 불일치 → 그 캐릭터 보석 행 전부 대체(5분 뒤 재조회), (d) 3·4레벨 광휘: 현재 낀 보석은 툴팁의 `기본 공격력 N% 증가`를 그대로 복원하므로 3·4레벨을 껴도 대체되지 않는다. 툴팁에 그 문구가 없는 예외적인 경우에만 표 값(null)을 찾다가 그 캐릭터 보석 행 전부가 대체된다. **목표 레벨이 3·4인 행**(1~3레벨에서 올리는 후보)은 표에 공격력 값이 없어 그 행만 대체된다(공식 수치 확인 전), (e) 표에 없는 스킬·보석 종류 미지·대상 보석 없음 → 그 행만 대체. 표시 계층은 사유를 구분하지 않고 §3의 푸터 문구만 낸다.
