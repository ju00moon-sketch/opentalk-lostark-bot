# 떠돌이 상인 `/떠상` — 설계 (2026-09-07)

사용자 요청: 다른 봇처럼 "전체 서버 떠상 정보"를 한 판으로 보고 싶다 — 서버별로 전설 호감도 몇 개, 전설 카드(에스더 시엔·진저웨일 등) 이름, 판매 마감까지 남은 시간.

## 1. 목표와 비목표

- 목표: `/떠상`이 8개 서버의 현재 떠돌이 상인 판매 요약을, `/떠상 서버`가 그 서버의 대륙별 상인·판매 품목 상세를 디스코드와 카톡에 같은 내용으로 보여 준다.
- 비목표: 제보 등록·추천(읽기 전용), 알림(선발신), 통계·과거 기록, 상인 위치 지도, 공식 API에 없는 값의 추측. 제보되지 않은 대륙을 채워 넣지 않는다.

## 2. 데이터 출처 (조사 2026-09-07)

- 공식 오픈 API에는 떠돌이 상인 정보가 없다. 클로아(kloa.gg 떠돌이 상인 페이지)는 한국 로아 통합 디스코드 커뮤니티 API `https://api.korlark.com`에서 받아 그린다(페이지 스크립트의 `apiUrl`, 실시간은 `wss://socket.korlark.com`). 다른 떠상 봇들도 같은 출처를 쓴다.
- `GET /lostark/merchant/scheme` → `{ schedules: [{ dayOfWeek 0~6, startTime "HH:MM:SS", duration "05:30:00", groups: [..] }], regions: [{ id, name(대륙), npcName, group 1~3, items: [{ id, type, name, grade, icon, default, hidden }] }] }`. 하루 4회(04·10·16·22시 KST), 회당 5시간 30분, 회차마다 출현 대륙 그룹이 다르다. 대륙 22곳. 아이템 `type` 1=카드, 2=호감도, 3=기타(관측), `grade` 1~4(4=전설). "전설 호감도"(id 239)와 이름 있는 전설 호감도 아이템(강태공의 낚싯대 등)이 모두 type 2·grade 4다.
- `GET /lostark/merchant/reports?server=<1~8 또는 영문>` → `[{ startTime, endTime, reports: [{ id, status, regionId, itemIds: [..], user, upVoteCount, createdAt }] }]`. 서버 번호 1 루페온 · 2 실리안 · 3 아만 · 4 아브렐슈드 · 5 카단 · 6 카마인 · 7 카제로스 · 8 니나브(클로아 스크립트의 매핑). 한글 이름은 400. 인증 없이 응답한다. 관측한 `status`는 전부 2였다 — 의미(정상/반려/삭제)는 기술 담당이 확인해 정상 제보만 쓴다.
- 약관: 클로아 이용약관에는 서비스 밖 이용을 제한하는 조항이 있고 커뮤니티 API 자체의 약관은 확인하지 못했다(회색 지대, 사용자 인지). 그래서 **명령 때만 조회·짧은 캐시·출처 표기**를 규칙으로 둔다. 고정 자료(시간표 1벌·서버별 제보 8벌, 2026-09-06 22시 창)는 `%TEMP%/opentalk-merchant-fixtures/`에 보관해 테스트에 쓴다.

## 3. 사용자 흐름과 출력

입력: `/떠상`(별칭 `ㄸㅅ`) · `/떠상 서버`(예: `/떠상 루페온`, `ㄸㅅ 카단`). 카톡은 `/떠상`·`.떠상`·`/ㄸㅅ` 동일(접두사 없는 초성은 기존대로 침묵).

전체 요약(디스코드 임베드 설명 / 카톡 평문) — 서버 순서 고정(루페온·실리안·아만·아브렐슈드·카단·카마인·카제로스·니나브):
```
❙ 전체 서버 떠상 정보            ← 카톡 제목(디스코드는 임베드 제목 "🧭 전체 서버 떠상 정보")

루페온: 전설호감도 1개
실리안: 전설호감도 4개
카단: 전설호감도 2개, 에스더 시엔
니나브: 전설호감도 3개, 진저웨일
…(8줄)

판매 마감까지 3시간 42분 남았습니다 (03:30까지)

※ 제보 기준 23:52 · 미제보 대륙은 빠질 수 있어요 · 자료: 클로아(KORLARK) 제보
```
- 한 서버 줄 = `이름: 전설호감도 N개` + 전설 카드가 있으면 `, 카드명, 카드명`(이름은 API 아이템 이름 그대로 — "에스더 시엔", "진저웨일"). 전설 카드가 없으면 카드 부분 생략. N은 대표 제보에 전설 호감도(type 2·grade 4)가 포함된 대륙 수.
- 그 서버 조회가 실패했으면 `이름: 조회 실패`. 8개 모두 실패면 실패 문구(아래).
- 남은 시간: `H시간 M분`(1시간 미만이면 `M분`), 마감 시각은 KST `HH:MM`.
- 제보 기준 시각 = 8개 서버 대표 제보 중 가장 늦은 `createdAt`(KST HH:MM). 없으면 항목 생략.

서버 상세 `/떠상 루페온`:
```
❙ 루페온 떠상 정보 (판매 마감까지 3시간 42분)

아르테미스 · 벤: ★전설 호감도, 시이라, 영웅 호감도
유디아 · 루카스: 천둥, 자이언트 웜, 영웅 호감도
…(제보된 대륙, 대륙 id 순)

미제보: 루테란 서부(말론), 토토이크(올리버)

※ 제보 기준 23:52 · 자료: 클로아(KORLARK) 제보
```
- 품목은 대표 제보의 아이템 이름을 API 순서대로, 전설(grade 4)은 앞에 `★`. 미제보는 이번 창에 출현하는 대륙 중 제보가 없는 곳만.
- 서버 이름이 목록에 없으면: `서버 이름을 확인해 주세요 (루페온·실리안·아만·아브렐슈드·카단·카마인·카제로스·니나브)`.

판매 창이 없을 때(전체·상세 공통): `지금은 떠돌이 상인이 없어요\n다음 출현: 오늘 16:00 (5시간 30분 판매)` — 오늘/내일/요일은 KST 기준.
조회 실패(네트워크·형식): `떠돌이 상인 정보를 가져오지 못했어요. 잠시 후 다시 시도해 주세요`.
카톡은 `layout.js`의 `TITLE`·`NOTE`를 쓰고 항목 사이 빈 줄, 공백 정렬 표 금지. 길이는 요약 약 300자·상세 최대 약 900자로 1,500자 안이며 전체 보기 링크는 만들지 않는다. 후속 안내 블록은 없다(2026-09-06 규칙).

## 4. 구조와 분담

- `src/merchant.js`(**기술 담당**): korlark 조회·집계·캐시. 계약은 5절. 요청마다 5초 시간 제한, 실패는 예외 대신 `null`/서버별 `ok:false`. 캐시: 시간표 24시간, 전체 판·서버 상세 각 60초, 진행 중 조회 공유. 요청은 명령이 올 때만 보내며 전체 판은 서버당 1회(8회). UA는 봇 이름으로 명시.
- `src/commands/merchant.js`(**기획 담당**): `/떠상 [서버]` 정의, 인자 검증, 3절 출력(디스코드·카톡), 실패 문구. `createExecute({ getMerchantBoard, getMerchantServer })` 공장으로 코어를 주입해 테스트한다. 별칭 `ㄸㅅ`(`text-commands.js`), `index.js` 등록, `help.js`·README·`docs/index.html` 행.
- 통합 책임자: 기획 담당(명령 진입점). 코어가 오기 전에는 `src/merchant.js`에 계약 서명만 있는 자리표시(항상 `null`)를 두어 봇이 기동되게 했고, 기술 담당이 파일을 통째로 교체했다(2026-09-07). 명령은 **코어 조회가 끝난 뒤의 시각**으로 창을 판정한다 — 조회 중 출현 경계를 넘기면 조회 전 시각으로는 정상 창을 '없음'으로 잘못 판단하기 때문(기술 검토 P2 반영).

## 5. 인터페이스 계약 — `src/merchant.js`

```js
export const SERVERS = [ { id: 1, name: '루페온' }, { id: 2, name: '실리안' }, { id: 3, name: '아만' }, { id: 4, name: '아브렐슈드' },
  { id: 5, name: '카단' }, { id: 6, name: '카마인' }, { id: 7, name: '카제로스' }, { id: 8, name: '니나브' } ];

export async function getMerchantBoard(): Promise<MerchantBoard | null>       // null = 시간표 조회 실패 등 판 자체를 만들 수 없음
export async function getMerchantServer(serverId): Promise<MerchantServer | null> // null = 조회 실패. 알 수 없는 id도 null

MerchantBoard = {
  fetchedAt: number,                                   // epoch ms
  window: { startsAt: number, endsAt: number } | null, // 지금 진행 중인 판매 창(epoch ms). 없으면 null
  next: { startsAt: number, endsAt: number } | null,   // 다음 창(window가 null일 때 채움; 있어도 채워도 됨)
  servers: [{ id, name, ok: boolean,                   // ok=false면 그 서버 조회 실패(아래 값은 0/[]/null)
    legendaryRapport: number,                          // 대표 제보에 전설 호감도(type 2·grade 4)가 있는 대륙 수
    legendaryCards: string[],                          // 대표 제보들의 전설 카드(type 1·grade 4) 이름, 중복 제거, 대륙 id 순
    reportedRegions: number, totalRegions: number,     // 이번 창에 출현하는 대륙 중 제보된 수 / 전체 수
    latestReportAt: number | null }],                  // 대표 제보 중 가장 늦은 createdAt
}
MerchantServer = {
  id, name, fetchedAt, window, next,                   // window·next는 MerchantBoard와 같은 의미
  regions: [{ regionId: string, regionName, npcName,
    items: [{ name, kind: 'card' | 'rapport' | 'etc', grade: 0 | 1 | 2 | 3 | 4 }],  // 대표 제보의 아이템, API 순서(0 = 모르는 아이템)
    reportedAt: number, upVotes: number }],            // 대륙 id 오름차순
  unreportedRegions: [{ regionName, npcName }],        // 이번 창 출현 대륙 중 제보 없음, 대륙 id 순
}
```
집계 규칙(기술 담당 구현, 기획 검증):
- 현재 창 = reports 응답 중 `startTime ≤ now < endTime`인 항목. 없으면 `window: null`, `next`는 시간표에서 KST 기준 다음 (dayOfWeek, startTime)을 찾아 `startsAt`·`endsAt(= +duration)`.
- 이번 창의 출현 대륙 = 시간표에서 현재 창에 해당하는 `groups`에 속한 대륙(`totalRegions`). 창은 있는데 시간표 매칭이 안 되면 전체 22곳으로 두고 로그.
- 대륙별 대표 제보 = 정상 status 중 `upVoteCount` 최대, 같으면 `createdAt` 최신. status는 클로아 공개 페이지의 enum으로 확인(2026-09-07): 0 보류·1 반려·2 승인·3 확정 — **2·3만 정상으로 집계**하고 0·1·미지 값은 제외(코드 주석에도 기록).
- 아이템 이름·종류·등급은 시간표의 `regions[].items`에서 id로 찾는다. 모르는 id는 `{ name: '알 수 없는 아이템', kind: 'etc', grade: 0 }`로 두고 세지 않는다.
- 시각은 모두 epoch ms로 넘기고 표시 계층이 KST로 바꾼다. 캐시 히트도 `fetchedAt`은 실제 조회 시각.

## 6. 검증 기준

코어(기술 담당) — 고정 자료(`%TEMP%/opentalk-merchant-fixtures/`, 2026-09-06 22:00 창)로:
1. 8개 서버 요약이 `루페온 0 / 실리안 2 / 아만 1 / 아브렐슈드 1 / 카단 0+에스더 시엔 / 카마인 2+에스더 시엔 / 카제로스 1 / 니나브 1+진저웨일`(기획이 같은 규칙으로 계산한 값)과 일치, `reportedRegions` 7, `totalRegions`는 22:00 일요일 창의 그룹 [2] 대륙 수.
2. 창 없음(고정 시각을 창 밖으로) → `window: null`, `next`가 시간표의 다음 회차. 서버 1개 실패 → 그 서버만 `ok:false`, 나머지 정상. 시간표 실패 → `null`.
3. 캐시: 60초 안 재호출 0회, 동시 요청 공유, 실패 미캐시. 요청 시간 제한 5초. 모르는 아이템 id 처리.

명령·표시(기획 담당):
4. 3절 출력 3종(요약·상세·창 없음)과 실패·서버 오류 문구가 양 플랫폼에 나오고, 카톡 요약 ≤ 400자·상세 ≤ 1,500자. 정의 수 +2(`떠상`·`ㄸㅅ`), 매처 `ㄸㅅ`/`.떠상`/`/떠상 루페온`. 경계: 조회 중 출현 시각을 넘겨도 정상 창을 표시하고, 조회 중 종료 시각을 넘기면 다음 출현 안내.
5. 통합: 실 API로 요약·상세 1회씩 확인(제보 수는 시점에 따라 다르므로 형식만), 디스코드·카톡 기존 명령 무영향.

검증 기록(2026-09-07): 코어 31건·기획 5건(경계 1건 포함)·연동 4건 통과. 실 API(일요일 22:00 창, 01:17 KST) 카톡 요약 238자·루페온 상세 404자(캐시 0ms), 디스코드 임베드 본문·푸터가 카톡 본문에 포함, `.떠상`·`/ㄸㅅ`·`.ㄸㅅ 루페온` 동일 응답, 서버 이름 오류 문구, `ㅂㅂㄱ`·`/도움말` 기존 동작 유지(카톡 도움말 전체 보기에 떠상 행·`ㄸㅅ` 안내 포함). 정의 95(기존 93 동일).

## 7. 배포 전제·위험·결정

- 재등록 필요(정의 +2). 새 환경변수·폰 스크립트 변경 없음. 홈페이지 배지·패치노트는 출시 담당.
- 위험: 커뮤니티 API 변경·중단 → 실패 문구로 끝나고 다른 명령에 영향 없음. 약관 회색 지대 → 출처 표기·명령 때만 조회·60초 캐시로 부하를 최소화하고 사용자가 인지한 상태로 운영. 제보 기반이라 빠진 대륙이 있을 수 있음 → 미제보 표시.
- 결정(2026-09-07): 출처 = korlark 커뮤니티 API(클로아와 동일), 형식은 사용자가 보여 준 다른 봇 출력에 맞추되 제보 기준 시각·미제보 안내·출처를 덧붙인다. 전설 카드 이름은 API 이름 그대로. 코어 = 기술 담당, 명령·출력·문서 = 기획 담당, 통합 = 기획.
