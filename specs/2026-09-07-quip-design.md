# 카카오톡 전용 오늘의 한마디 `/한마디` — 설계 (2026-09-07)

사용자 요청: "/한마디 커맨드도 넣을려고하는데 명령어칠때마다 매번 랜덤 한마디 1~2줄정도 뽑게" → 고정 목록 대신 "LLM연결해서는 불가능?" → "1번으로 하고 사용자는 하루에 한번씩만 들을수있게". 결정: LLM 생성 + 고정 목록 대체, 사용자당 하루 1회. 이 기능에 한해 코드·문서에 API 제공자·모델 이름을 쓴다(작성자 표시가 아니라 제품 의존성).

**최종 플랫폼 결정(2026-09-07)**: 한마디는 카카오톡 전용이다. 디스코드 슬래시·텍스트 목록에서는 제외하며 생성·저장 코어는 그대로 유지한다.

## 1. 목표와 비목표

- 목표: 카카오톡 `/한마디`·`.한마디`·`/ㅎㅁㄷ`·`.ㅎㅁㄷ`를 치면 LLM이 길드 채팅용 한마디 1~2줄을 새로 만들어 준다. 사용자당 하루(한국 시간 자정 기준) 한 번만 새 한마디를 만들고, 같은 날 다시 부르면 그날 받은 한마디를 다시 보여 준다. 키가 없거나 호출이 실패·지연되거나 봇 전체 하루 상한을 넘기면 고정 목록에서 뽑는다.
- 비목표: 대화·후속 질문, 사용자 입력을 프롬프트에 넣는 자유 생성, 한마디 저장·랭킹, 관리자 주제 설정, 카톡 접두사 없는 `ㅎㅁㄷ`. 요청되면 별도.

## 2. 생성 규칙과 안전장치

- 제공자·모델: 클로드 API 공식 SDK `@anthropic-ai/sdk`(`client.messages.create`). 모델은 환경변수 `QUIP_MODEL`, 기본 `claude-haiku-4-5`(가장 저렴, 한 번에 약 200토큰 → 0.5원 미만). 키는 SDK 기본 환경변수 `ANTHROPIC_API_KEY`(서버 `.env`, 값은 채팅·문서에 쓰지 않는다). 키가 없으면 SDK 클라이언트를 만들지 않고 항상 고정 목록.
- 프롬프트: 시스템 — 로스트아크 길드 봇의 '오늘의 한마디', 한국어 1~2줄 60자 이내, 유머·응원·짧은 명언 중 하나, 게임 용어는 자연스럽게, 사람 이름·욕설·비하·정치·종교 금지, 이모지 최대 1개, 따옴표·머리말 없이 문장만, 읽는 사람에게 직접 건네는 존댓말로 이름·호칭 없이 바로 이어질 말로 시작(봇이 앞에 "○○님"을 붙인다 — 이름은 프롬프트에 넣지 않는다). 사용자 메시지 — `주제 힌트`(고정 목록의 주제 24개 중 무작위)·`톤`(유머/응원/명언 무작위)·날짜. 사용자 입력은 프롬프트에 들어가지 않는다(주입 불가).
- 요청: `max_tokens 200`, `temperature 1`, 재시도 0(`maxRetries: 0`), 제한 시간 4초(`timeout` + `signal: AbortSignal.timeout(4000)` — SDK `timeout`은 본문 수신까지 막지 못해 둘 다 넘긴다, 기술 검토 P2-2 반영). 응답은 첫 `text` 블록만 쓰고, 앞뒤 따옴표·공백 제거, 줄은 최대 2줄, 비어 있거나 120자 초과·`stop_reason` `refusal`이면 실패로 본다. 실패는 로그 1줄(본문·키 미출력) 후 고정 목록.
- 하루 1회: 루트 `quip-daily.json` `{ "<userId>": { "date": "YYYY-MM-DD", "text", "source": "llm"|"list" } }`. `json-store.js`의 `readJson`/`writeJsonAtomic`(깨진 파일이면 저장 거부 → 실패 문구). 사용자 ID는 출석 체크와 같은 카톡 브리지 키 `kakao:oc:<닉>`이다.
- 봇 전체 하루 상한: 메모리 카운터(날짜별, 재시작 시 0) 300회. 넘으면 호출 없이 고정 목록. LLM 호출 시도마다 1 증가(성공·실패 모두).
- 동시성(기술 검토 P2-1 반영): 생성을 기다리는 수 초 동안 다른 요청이 저장할 수 있으므로 ① 같은 사용자·같은 날의 진행 중 요청은 한 프로미스를 공유하고(LLM 1회), ② 저장 직전에 파일을 다시 읽어(검증 포함) 내 항목만 덧붙이며(다른 사용자 기록 보존), ③ 그사이 같은 사용자에게 같은 날 또는 더 뒤 날짜의 기록이 생겼으면 덮어쓰지 않고 그 기록을 돌려준다(자정을 넘겨 끝난 전날 요청이 다음 날 기록을 지우지 않음).
- 저장 구조 검증(출석 체크 기술 검토 P2-1과 같은 결함 예방): 루트가 객체가 아니거나 항목의 `date`(`YYYY-MM-DD`)·`text`(문자열)·`source`(`llm`|`list`)가 형식에 안 맞으면 손상으로 보고 `CorruptStoreError` → 저장·백업 없이 실패 문구.
- 고정 목록: `src/data/quips.js` 60줄(1~2줄, 80자 이내, 고유). 직전에 그 사용자가 받은 문장은 피한다.

## 3. 입력과 출력

- 카톡: `/한마디`, `.한마디`, `/ㅎㅁㄷ`, `.ㅎㅁㄷ`(접두사 없는 `ㅎㅁㄷ`는 침묵). 디스코드에서는 슬래시 `/한마디`·`/ㅎㅁㄷ`를 등록하지 않고 `ㅎㅁㄷ`·`.한마디`도 처리하지 않는다.
- 새 한마디(사용자 지정 양식 "(카카오톡 이름)님 ~~~"): `블레상돈님 {한마디}` — 머리말 없이 이름 뒤에 바로 이어진다.
- 같은 날 재요청: `블레상돈님 {그날 받은 한마디}\n(오늘 한마디는 이미 받았어요 · 내일 00:00 한국 시간에 새 한마디)`
- 저장 실패: `한마디를 준비하지 못했어요. 잠시 후 다시 시도해 주세요`
- 출처(llm/list)는 사용자에게 표시하지 않는다. 이름은 카톡 닉네임을 사용하며 없으면 "회원"으로 표시한다. 별명과 생성 문장이 답장에 들어가므로 `allowedMentions: { parse: [] }`로 멘션 해석을 끈다.

## 4. 구조와 분담

제품 단독 구현. 외부 API·비밀 키·저장이라 기술 교차 검토 대상.

- 신규 `src/data/quips.js`: `QUIPS`, `QUIP_TOPICS`.
- 신규 `src/quip.js`: `pickFallback`, `buildRequest`, `generateQuip`, `getQuip`, `createClient`.
- 신규 `src/commands/quip.js`: `/한마디`, `createExecute({ getQuip, now })`.
- `src/commands/index.js`의 `kakaoCommands`에만 포함, `src/text-commands.js` 별칭 `ㅎㅁㄷ`, `.gitignore`에 `quip-daily.json`, `package.json`에 `@anthropic-ai/sdk`(배포 시 `npm install`), README 환경변수·행, help·`docs/index.html` 행. 디스코드 기본 명령 58개에는 한마디를 포함하지 않으며 별칭 슬래시도 등록하지 않는다.

## 5. 인터페이스 계약

- `pickFallback({ random, avoid })` → 고정 목록 문자열(`avoid`와 다른 것).
- `buildRequest({ model, random, date })` → `{ model, max_tokens, temperature, system, messages }`.
- `generateQuip({ client, model, random, now, timeoutMs })` → 정규화한 문자열 또는 `null`.
- `getQuip(userId, { now, random, generate, storePath, cap })` → `{ status: 'new'|'repeat', text, source, date }`. 깨진 저장 파일이면 `CorruptStoreError`.
- 명령 `createExecute({ getQuip, now })`.

## 6. 검증 기준

1. 고정 목록: 50개 이상·고유·2줄 이내·80자 이내. `pickFallback`이 `avoid`를 피함.
2. 요청 형식: 기본 모델·`max_tokens`·`temperature`·시스템 프롬프트 핵심 규칙·사용자 메시지 주제/톤, 사용자 입력 미포함.
3. 응답 정규화: 따옴표 제거·2줄 자름·빈 응답/120자 초과/`refusal`/예외/시간 초과 → `null`, `timeout`·`maxRetries` 전달.
4. `getQuip`: 첫 호출 LLM 사용·저장, 같은 날 재요청은 저장된 문장·LLM 미호출, 다음 날 새로, LLM `null`·생성기 없음·상한 초과 → 고정 목록(직전 문장 회피), 깨진 파일 예외.
5. 명령 문구(새/재요청/실패), 카톡 닉네임 표시.
6. 등록: 디스코드 목록에 한마디·ㅎㅁㄷ가 없고 텍스트 입력도 미처리. 카톡 `.한마디`·`/한마디`·`/ㅎㅁㄷ`·`.ㅎㅁㄷ`와 접두사 없는 `ㅎㅁㄷ` 침묵을 확인한다.
7. 실제 경로: 키 없는 상태에서 카톡 브리지로 고정 목록 응답 → 재요청 반복 확인. 실제 LLM 호출은 키가 있는 환경(서버 `.env` 또는 로컬 `.env.dev`)에서 1회 확인 — 로컬에 키가 없어 이번에는 미완.

## 7. 배포 전제·위험·결정

- **새 의존성** `@anthropic-ai/sdk` → 배포 절차 4번(의존성 설치) 필요. 한마디 자체는 카톡 전용이라 슬래시 추가 등록이 없으며, 이번 플랫폼 정책 적용 시 디스코드 목록은 기본 58개로 재등록한다. 서버 `.env`에 `ANTHROPIC_API_KEY`(사용자 발급, 기술 등록), 선택 `QUIP_MODEL`. 키가 없으면 고정 목록으로만 동작하므로 배포 순서는 자유.
- 위험: API 장애·지연은 4초 뒤 고정 목록으로 넘어가 사용자 체감은 응답 지연 최대 4초. 비용은 하루 상한 300회 × 약 0.5원. 생성 문장의 품질·적절성은 프롬프트 규칙과 60자 제한에 의존하며 사후 검열은 없다(부적절하면 프롬프트 조정 또는 키 제거로 고정 목록만).
- 결정: 하루 1회는 카톡 사용자 ID 기준, 같은 날 재요청은 같은 문장 재표시, 고정 목록 60줄은 제품이 작성(사용자가 파일에서 수정 가능).
