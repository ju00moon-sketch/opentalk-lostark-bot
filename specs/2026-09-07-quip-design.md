# 카카오톡 전용 오늘의 한마디 `/한마디` — 설계 (2026-09-07)

사용자 요청: "/한마디 커맨드도 넣을려고하는데 명령어칠때마다 매번 랜덤 한마디 1~2줄정도 뽑게" → 고정 목록 대신 "LLM연결해서는 불가능?" → "1번으로 하고 사용자는 하루에 한번씩만 들을수있게". 결정: LLM 생성 + 고정 목록 대체, 사용자당 하루 1회. 이 기능에 한해 코드·문서에 API 제공자·모델 이름을 쓴다(작성자 표시가 아니라 제품 의존성).

**최종 플랫폼 결정(2026-09-07)**: 한마디는 카카오톡 전용이다. 디스코드 슬래시·텍스트 목록에서는 제외하며 생성·저장 코어는 그대로 유지한다.

## 1. 목표와 비목표

- 목표: 카카오톡 단독 `한마디`·`ㅎㅁㄷ` 또는 `/한마디`·`.한마디`·`/ㅎㅁㄷ`·`.ㅎㅁㄷ`를 치면 오늘 하루에 건네는 짧은 응원·생각거리를 새로 만들어 준다. 사용자당 하루(한국 시간 자정 기준) 한 번만 새 한마디를 만들고, 같은 날 다시 부르면 본문 없이 다음 날 00:00(한국 시간) 이후 재시도 안내만 보낸다. 키가 없거나 호출이 실패·지연되거나 봇 전체 하루 상한을 넘기면 고정 목록에서 뽑는다.
- 비목표: 대화·후속 질문, 사용자 입력을 프롬프트에 넣는 자유 생성, 한마디 랭킹, 관리자 주제 설정. `한마디 해주세요`처럼 뒤에 말을 붙인 일반 대화는 단독 명령으로 처리하지 않는다.

## 2. 생성 규칙과 안전장치

- 제공자·모델: 새 설정 권장값은 OpenAI `gpt-5.6-sol`, Responses API를 Node.js 24 내장 `fetch`로 호출한다. 기존 Anthropic `@anthropic-ai/sdk`와 `claude-haiku-4-5`도 유지한다. `QUIP_PROVIDER=openai|anthropic` 명시 → `QUIP_MODEL`의 `gpt-`/`claude-` 접두어 → 사용 가능한 키 순서로 하나를 고른다. 두 키가 있고 명시 설정이 없으면 OpenAI. 명시 제공자의 키가 없거나 모델 접두어와 제공자가 다르거나 알 수 없는 제공자이면 클라이언트 없이 고정 목록. 키는 `OPENAI_API_KEY`·`ANTHROPIC_API_KEY`이며 값은 채팅·문서에 쓰지 않는다.
- 프롬프트: 한국어 존댓말로 일상 속 응원·공감·짧은 창작 격언과 자연스러운 가벼운 농담, 대체로 두 문장·45~75자를 목표로 하되 최대 2줄·80자. 이름님 뒤에 바로 이어지는 문장만 출력하고 이름·호칭·당신·머리말은 넣지 않는다. 소재와 분위기에 어울리면 문장 끝에 이모지 1개를 가볍게 곁들이고, 매번 강제하거나 여러 개를 붙이지 않는다. 일상을 다루되 훈계·억지 게임 용어·운세·성공 보장·허위 인용·욕설·비하·정치·종교·광고·해시태그를 피한다. 억지 의인화·비유, 매번 교훈으로 끝내기, 상대의 경험·계절·날씨 추측과 차·물·휴식의 상투적인 소재를 피한다. 유머·격언 비율은 정하지 않으며, 창작 격언에 저자나 출처를 붙이지 않는다. 요청 입력은 구체적인 일상 소재 24개 중 하나뿐이며 날짜·이름·사용자 메시지는 전송하지 않는다. 날짜는 하루 제한과 저장에서만 사용한다. 실제 생성 시 소재 목록을 섞어 하나씩 소진하고 다시 섞는다. 바퀴 경계의 연속 같은 소재도 피한다. 덱은 한 프로세스의 메모리에만 있으며 재시작 시 초기화한다. 실패한 호출도 소재를 소비하지만 키 없음·당일 재요청·상한 초과는 소비하지 않는다.
- 요청: OpenAI는 `max_output_tokens:200`·`store:false`·기본 모델 `reasoning.effort:none`, Anthropic은 `max_tokens:200`·`temperature:1`. 출력 상한에는 입력 토큰이 포함되지 않는다. 재시도 없이 한 제공자만 한 번 호출하며 연결부터 본문 수신까지 `AbortSignal.timeout(12000)`으로 제한한다(기존 SDK는 `timeout:12000`·`maxRetries:0`도 전달). OpenAI 응답과 message 상태는 completed, 내용 블록은 output_text만 허용하며 Anthropic은 end_turn·text만 허용한다. 거부·잘림·실패·빈 응답·80자 또는 2줄 초과는 null → 고정 목록. 임의 모델 변경 시 옵션 호환성을 확인한다. 오류 로그에는 HTTP 숫자 또는 고정 오류 분류만 쓰고 본문·키는 쓰지 않는다.
- 하루 1회: 루트 `quip-daily.json` `{ "<userId>": { "date": "YYYY-MM-DD", "text", "source": "llm"|"list" } }`. `json-store.js`의 `readJson`/`writeJsonAtomic`(깨진 파일이면 저장 거부 → 실패 문구). 사용자 ID는 출석 체크와 같은 카톡 브리지 키 `kakao:oc:<닉>`이다.
- 봇 전체 하루 상한: 메모리 카운터(날짜별, 재시작 시 0) 300회. 넘으면 호출 없이 고정 목록. LLM 호출 시도마다 1 증가(성공·실패 모두).
- 동시성: 생성을 기다리는 동안 같은 사용자·같은 날의 요청은 한 프로미스를 공유한다. 저장 직전에 파일을 다시 읽어 검증하고, 중복 검사·선택·내 항목만 원자 저장하기 사이에는 비동기 대기가 없다. 그사이 같은 사용자에게 중복 없는 당일 기록이나 더 뒤 날짜의 기록이 생겼으면 그 기록을 돌려준다. 자정을 넘겨 끝난 전날 요청은 다음 날 기록을 지우지 않는다. 단일 실행 프로세스를 전제로 한다.
- 저장 구조 검증(출석 체크 기술 검토 P2-1과 같은 결함 예방): 루트가 객체가 아니거나 항목의 `date`(`YYYY-MM-DD`)·`text`(문자열)·`source`(`llm`|`list`)가 형식에 안 맞으면 손상으로 보고 `CorruptStoreError` → 저장·백업 없이 실패 문구.
- 문장 구분: 저장 직전 최신 상태에서 다른 사용자의 당일 본문과 본인의 직전 본문을 피한다. 공백·줄바꿈을 제거하고 유니코드 정규화한 본문으로 비교한다. 새 결과는 추가로 원문을 구두점·줄바꿈으로 나눈 뒤 정규화한다. 공백·문장부호·이모지를 뺀 첫 문장이 8자 이상으로 같거나 한 문장 안의 연속 16자 표현이 겹치면 추가 생성 없이 목록으로 대체하고 출처를 `list`로 저장한다. 같은 의미를 완전히 다른 말로 표현한 경우까지 판별하는 검사는 아니다.
- 고정 목록: `src/data/quips.js` 60개 중 부분 표현까지 겹치지 않는 후보를 먼저 고른다. 그런 후보가 없으면 전체 본문이 다른 후보를 고르고, 60개를 모두 사용했으면 한 문장으로 된 항목 두 개를 서로 다르게 묶어 최대 2줄·2문장·80자로 전한다. 해당 후보까지 모두 소진되면 중복을 저장하지 않고 기존 실패 문구를 돌려준다.
- 기존 중복: 같은 날 다른 사용자와 본문이 겹치는 기록은 그 사용자의 다음 호출에서 한 번 교체한다. 다른 사용자 기록은 바꾸지 않으며 이후 재요청은 새 문장을 유지한다. 교체 시에는 새 한마디 양식으로 전하고, 그 뒤 재요청에는 §3의 안내만 보낸다. 저장 구조와 사용자 식별 방식은 유지한다. 같은 닉네임은 같은 사용자로 인식하므로 구분할 수 없다.

## 3. 입력과 출력

- 카톡: 단독 `한마디`, `ㅎㅁㄷ`(앞뒤 공백 허용), `/한마디`, `.한마디`, `/ㅎㅁㄷ`, `.ㅎㅁㄷ`. 디스코드에서는 슬래시 `/한마디`·`/ㅎㅁㄷ`를 등록하지 않고 `ㅎㅁㄷ`·`.한마디`도 처리하지 않는다.
- 새 한마디(사용자 지정 양식 "(카카오톡 이름)님 ~~~"): `블레상돈님 {한마디}` — 머리말 없이 이름 뒤에 1~2줄 본문만 이어지며 하단 안내를 붙이지 않는다.
- 같은 날 재요청(`status: 'repeat'`): `오늘의 한마디는 이미 받으셨어요. 내일 00:00(한국 시간) 이후에 다시 시도해 주세요.` — 이름과 저장된 본문 없이 이 안내만 보낸다. 생성·저장 코어는 기존 기록을 유지하며 추가 생성하지 않는다.
- 저장 실패: `오늘의 한마디를 준비하지 못했어요. 잠시 후 다시 시도해 주세요`
- 출처(llm/list)는 사용자에게 표시하지 않는다. 이름은 카톡 닉네임을 사용하며 없으면 "회원"으로 표시한다. 별명과 생성 문장이 답장에 들어가므로 `allowedMentions: { parse: [] }`로 멘션 해석을 끈다.

## 4. 구조와 분담

최초 구현은 제품 담당. 이번 오늘의 한마디 개편은 기술이 전체 구현하고 제품이 방향 논의·독립 교차 검토를 맡는다. 외부 API·응답 해석 변경으로 교차 검토 대상이다.

- 신규 `src/data/quips.js`: `QUIPS`, `QUIP_TOPICS`.
- 신규 `src/quip.js`: `pickFallback`, `buildRequest`, `generateQuip`, `getQuip`, `createClient`.
- 신규 `src/commands/quip.js`: `/한마디`, `createExecute({ getQuip, now })`.
- `src/commands/index.js`의 `kakaoCommands`에만 포함, `src/text-commands.js` 별칭 `ㅎㅁㄷ`, `.gitignore`에 `quip-daily.json`, `package.json`에 `@anthropic-ai/sdk`(배포 시 `npm install`), README 환경변수·행, help·`docs/index.html` 행. 디스코드 기본 명령 58개에는 한마디를 포함하지 않으며 별칭 슬래시도 등록하지 않는다.

## 5. 인터페이스 계약

- `pickFallback({ random, avoid, exclude })` → 고정 목록 또는 두 문장 조합(`avoid`·`exclude`에 있는 본문 회피). 모든 후보 소진 시 예외.
- `buildRequest({ provider, model, random, topic })` → 제공자별 요청 본문. 기본 제공자는 openai.
- `createClient({ env, fetchImpl })` → 선택한 provider·model·호출 객체 또는 null. 지정한 env의 키를 사용한다.
- `generateQuip({ client, model, random, timeoutMs })` → 정규화한 문자열 또는 `null`.
- `getQuip(userId, { now, random, generate, storePath, cap })` → `{ status: 'new'|'repeat', text, source, date }`. 깨진 저장 파일이면 `CorruptStoreError`.
- 명령 `createExecute({ getQuip, now })`.

## 6. 검증 기준

1. 고정 목록: 50개 이상·고유·2줄 이내·80자 이내. `pickFallback`이 `avoid`를 피함.
2. 요청 형식: 제공자 선택·기본 모델·추론 없음·출력 상한·store:false·시스템 핵심 규칙·일상 소재 하나, 날짜·사용자 입력 미포함.
3. 응답 정규화: 따옴표 제거·빈 응답/80자 초과/2줄 초과/거부/잘림/예외/시간 초과 → null. 연결과 본문 제한·재시도 없음·다른 제공자 추가 호출 없음·로그 비밀값 미출력.
4. `getQuip`: 첫 호출 LLM 사용·저장, 같은 날 재요청은 저장된 문장·LLM 미호출, 다음 날 새로, LLM `null`·생성기 없음·상한 초과 → 고정 목록(직전 문장 회피), 깨진 파일 예외.
5. 명령 문구: 새 요청은 카톡 닉네임과 1~2줄 본문만, 같은 날 재요청은 다음 날 안내만, 실패는 기존 실패 문구. 다음 날에는 새 한마디 양식으로 표시.
6. 등록: 디스코드 목록에 한마디·ㅎㅁㄷ가 없고 텍스트 입력도 미처리. 카톡 단독 `한마디`·`ㅎㅁㄷ`, 기존 `.한마디`·`/한마디`·`/ㅎㅁㄷ`·`.ㅎㅁㄷ` 및 일반 대화의 침묵을 확인한다.
7. 실제 경로: 키 없는 상태에서 카톡 브리지로 고정 목록 응답 → 재요청 반복 확인. 생성 API의 실제 사용 토큰·속도·문장 품질은 키 있는 환경에서 별도로 확인하며, 키 없는 격리 검증을 실제 생성 검증으로 쓰지 않는다.

## 12. 입력 압축과 가벼운 유머 보완

- 생성 지침의 중복 설명을 줄이고, 날짜를 요청에서 제외한다. 요청에는 일상 소재 하나만 넣으며 하루 제한·자정 판단·저장 날짜는 기존 코어에서 처리한다. 소재 순환·중복 검사·1~2줄/80자 제한·선택적 이모지·12초 기한은 유지한다.
- 웃음은 공감할 만한 일상 실수와 상황의 반전에서 찾는다. 유머 확률이나 필수 농담은 없고, 응원·공감만으로 끝나는 답도 허용한다. 상대가 실제로 겪은 일로 단정하지 않도록 가정·일반적인 상황으로 표현한다.
- 첫 압축 시험은 같은 여섯 소재를 전후 순서를 번갈아 총 12회 호출했다. 입력은 평균 409.33→227.67토큰이었지만 경험 단정·억지 비유가 관찰되어 해당 지침을 보강했다. 이 초기 압축본은 최종 후보에서 제외했다.
- 최종본을 같은 여섯 소재로 6회 추가 확인했다. 평균 입력 256.67토큰으로 기존보다 37.30% 적고, 출력은 평균 36.17토큰·52자였다. 전부 생성 성공, 1~2줄·80자 이내, 추가 호출·시간 초과·목록 대체 없음. 이 표본은 이모지 없이 생성됐으며 이모지는 여전히 선택 사항이다.
- 최종 6회는 1,940~2,513ms·평균 2,249ms·중앙값 2,285ms였다. 앞서 같은 소재의 기존 지침 6회는 평균 2,727ms·중앙값 2,782ms·출력 40토큰이었다. 작은 순차 표본이며 출력량·서비스 변동도 달라 입력 축소만의 속도 효과나 향후 지연을 보장하지 않는다.
- 임시 저장소를 통한 실제 생성→중복 확인→저장 경로를 사용했다. 총 18회, 운영 환경·실사용자 기록 변경 및 채팅 발송 없음. 날짜 제거 후 같은 날 재요청의 추가 생성 없음과 자정 이후 새 생성, 두 제공자의 요청 형식과 기존 중복·지연 검증을 확인했다.

## 13. 짧은 창작 격언 추가

- 사용자 선택에 따라 응원·공감·가벼운 일상 유머와 함께 짧은 창작 격언도 자연스럽게 사용한다. 별도 선택 비율은 두지 않고 저자·출처를 붙이지 않으며, 허위 인용은 금지한다. 기존 이름 뒤 본문·길이·선택적 이모지·소재 하나만 입력하는 요청과 생성/저장 보호는 유지한다.
- 실제 생성·중복 검사·임시 저장 경로에서 네 소재를 시험해 4/4 생성 성공, 평균 48.25자·입력281토큰·출력34.5토큰이었다. 2,034~3,241ms·평균2,628.25ms, 시간 초과·추가 호출·실사용자 기록 변경·환경 변경·채팅 발송 없음. 앞선 입력 압축 통계는 이전 지침의 측정값이다.
