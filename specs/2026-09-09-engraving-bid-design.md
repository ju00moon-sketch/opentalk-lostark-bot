# 유물 각인서명 분배금 계산과 카톡 비싼 유각 초성

## 1. 범위

- 카카오톡에서 `ㅂㅆㅇㄱ`로 기존 유물 각인서 TOP 10과 전일 대비를 조회한다. `/ㅂㅆㅇㄱ`·`.ㅂㅆㅇㄱ`도 지원하며 기존 `/유각`·`.비싼유각`의 순위·페이지 동작을 유지한다.
- 분배금 채팅 명령은 숫자 가격 대신 각인서명을 받아 유물 등급의 권당 현재 최저가로 계산한다. 숫자를 직접 넣으면 기존 계산과 출력을 유지하며 시세 API를 호출하지 않는다.
- 디스코드 슬래시 `/분배금`의 필수 정수 `가격`과 선택 정수 `인원` 정의는 유지한다. 각인서명은 카톡 명령과 디스코드 텍스트 명령에서 사용한다.
- 기존 추천 입찰가·균등 분배 입찰가·재판매 원금 회수 상한 계산식, 4/8/16인 선택과 소수점 표시 방식은 바꾸지 않는다.

## 2. 입력

| 경로 | 예시 | 동작 |
|---|---|---|
| 카톡 | `ㅂㅆㅇㄱ`·`/ㅂㅆㅇㄱ`·`.ㅂㅆㅇㄱ` | 유물 각인서 순위 첫 쪽 |
| 카톡 | `ㅂㅆㅇㄱ 2` | 유물 각인서 순위 2쪽 |
| 카톡 | `/분배금 원한` | 유물 원한 각인서 시세로 4/8/16인 계산 |
| 카톡 | `.분배금 저주받은 인형 8` | 유물 저주받은 인형 각인서 시세로 8인 계산 |
| 카톡·디스코드 텍스트 | `ㅂㅂㄱ 원한 8`·`.분배금 원한 8` | 유물 원한 각인서 시세로 8인 계산 |
| 카톡·디스코드 텍스트 | `ㅂㅂㄱ 예둔 8`·`.분배금 저받 8` | 줄임말을 예리한 둔기·저주받은 인형으로 해석한 뒤 유물 시세로 계산 |
| 기존 숫자 입력 | `ㅂㅂㄱ 100000`·`/분배금 100000 8` | 기존 숫자 가격 계산 |

- 각인서명의 내부 공백을 보존한다. 끝의 선택 인원은 4·8·16 중 하나이며, 생략하면 세 인원을 모두 표시한다.
- 줄임말 7종(예둔→예리한 둔기, 돌대→돌격대장, 아드→아드레날린, 질증→질량 증가, 기습→기습의 대가, 타대→타격의 대가, 저받→저주받은 인형)을 정식 이름으로 바꿔 조회한다. 정식 이름·등록되지 않은 입력은 그대로 정확 일치 조회하며, 임의의 부분 이름으로 확장하지 않는다. 결과에는 입력이 줄임말이어도 정식 품명을 표시한다. 이 해석은 분배금 명령에만 적용한다.
- 순위 페이지는 기존과 같이 1~20의 정수만 허용한다. 범위를 벗어난 숫자·소수·잘못된 인수는 사용법을 안내한다.
- 유물 등급으로만 조회한다. 부분 일치 결과를 임의로 골라 계산하지 않는다.
- 접두사 없는 카톡 입력은 지정된 명령만 허용한다. 일반 대화 전체를 시세 검색으로 처리하지 않는다.

## 3. 가격 조회

- 기존 `searchMarketItems`를 사용한다. 각인서는 거래소 `POST /markets/items`, 카테고리 `40000`, 등급 `유물`의 자료다.
- 현재 등록 최저가인 `CurrentMinPrice`를 사용하며 `BundleCount`로 나눠 권당 가격으로 계산한다. 전일 평균가·최근 거래가로 대체하지 않는다.
- 정식 품명 `유물 {각인명} 각인서`와 `Grade: 유물`을 확인한다. 이름이 다른 부분 검색 결과나 다른 등급은 제외한다.
- 가격은 유한한 양수여야 하고 묶음 수는 유효한 양의 정수여야 한다. 검색 결과가 없거나 이름이 모호하거나 유효한 현재 가격이 없으면 계산하지 않고 안내한다.
- API 오류도 계산하지 않고 재시도 안내로 끝낸다. 실패를 0G나 임의 시세로 바꾸지 않는다.

## 4. 출력

각인서명 입력의 출력은 기존 제목 바로 아래에 정식 품명과 가격 기준을 한 줄 추가한다. 아래 100,000G는 형식 설명을 위한 예시 값이며 고정 시세가 아니다.

```text
분배금 계산기 — 시세 100,000G
유물 원한 각인서 · 현재 최저가

❙ 추천 입찰가 · 선점 기준
4인: 64,772G
8인: 75,568G
16인: 80,965G

❙ 균등 분배 입찰가
4인: 71,250G
8인: 83,125G
16인: 89,062G

❙ 재판매 원금 회수 상한
95,000G
```

인원을 지정하면 추천·균등 분배 구획에 해당 인원만 표시한다. 숫자 입력에서는 각인서 이름 줄을 추가하지 않는다. 디스코드 텍스트 명령도 같은 시세·각인서 이름·계산값을 기존 임베드 구성에 표시한다.

## 5. 검증 기준

1. 카톡 `ㅂㅆㅇㄱ`의 접두사 유무와 페이지 지정이 기존 유각 명령에 연결되는지 확인한다. 서버와 폰 입력 필터를 각각 확인한다.
2. 카톡·디스코드 텍스트 진입점에서 한 단어 이름과 공백이 있는 이름, 인원 생략·8인 지정의 최종 응답을 확인한다.
3. 숫자 입력은 기존 값·출력과 같고 시세 조회가 0회인지 확인한다. 디스코드 슬래시 명령 정의가 바뀌지 않았는지 비교한다.
4. 다른 등급·부분 일치·빈 결과·유효하지 않은 가격·API 실패에서 계산을 막는지 확인한다. 유효한 묶음 응답은 권당 가격으로 계산하는지 확인한다.
5. 도움말의 플랫폼별 입력 안내와 길이 제한, README·홈페이지 사용법·명세의 일치를 확인한다.

파서와 외부 응답 해석 변경이므로 독립 교차 검토 대상이다. 격리된 응답 자료 검증과 실제 API 조회·실제 채팅 도착 확인은 구분해서 기록한다.

## 6. 적용 전제

- 서버 소스와 폰의 `scripts/messengerbot-r.js` 입력 필터를 함께 적용한다. 폰 스크립트의 기존 `SERVER`·`ROOMS` 설정을 유지하고 재컴파일한다.
- 디스코드 슬래시 정의와 명령 수는 유지하므로 재등록이 필요 없다. 새 환경변수·의존성 설치·저장 형식 변경은 없다.
- 공개 업데이트 노트·버전·최신 업데이트 카드는 출시 범위 확정 뒤 실제 배포분에 맞춰 갱신한다.
