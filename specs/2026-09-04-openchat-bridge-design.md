# 카카오톡 오픈채팅방 브리지 — 설계 (2026-09-04, 채널 챗봇 설계의 후속)

`specs/2026-09-04-kakao-channel-bot-design.md`의 채널 1:1 챗봇을 만든 뒤, 사용자가 실제로 쓰려는 곳은 **길드 오픈채팅방**임이
확인됐다("오픈채팅방에서 쓸건데"). 카카오 공식 챗봇은 오픈채팅방에 들어갈 수 없으므로(방장봇은 고정 답변만), 사용자 결정으로
**폰의 메신저봇R이 방 메시지를 우리 서버에 넘기는 비공식 브리지**로 전환한다. 채널 챗봇용 스킬 엔드포인트는 그대로 남겨 두되
오픈빌더 신청·채널 생성은 하지 않는다.

## 1. 구조

```
오픈채팅방 메시지 ─▶ 카카오톡 알림 ─▶ 메신저봇R(안드로이드 폰, 봇 계정) ─POST { room, sender, text }─▶ http://서버/bridge/message/<secret>
                                                                                  │ handler.handleBridgeMessage → 기존 매칭·실행·변환
                                          방에 답장(replier.reply) ◀── { text } ◀─┘
```

- 서버: `src/kakao/server.js`에 `POST /bridge/message/<KAKAO_SKILL_SECRET>` 라우트. `src/kakao/handler.js`의 `handleBridgeMessage()`가
  `handleSkillRequest()`를 예산 25초로 호출하고 결과 JSON을 `flattenResponse()`로 평문 한 덩어리로 바꾼다.
- 폰: `scripts/messengerbot-r.js`(메신저봇R 레거시 API `response(room, msg, sender, …)`). `SERVER`만 채우면 된다. `ROOMS`는 선택 —
  비워 두면(기본) 봇 계정이 들어가 있는 모든 방·1:1에서 동작하므로 방을 옮기거나 제목을 바꿔도 손댈 게 없다(사용자 질문 2026-09-04
  "오픈채팅방 바뀌면 다시 나가지는 거야?"에 대한 답). `/`·`[`로 시작하는 메시지만 서버로 보내고, 답이 있으면 그 방에 쓴다. Jsoup POST, 30초 타임아웃, 응답은 `execute().body()`로
  원문 그대로(`.post().text()`는 줄바꿈을 지움).

## 2. 동작 규칙

- **이미지는 링크 미리보기 카드로**(사용자 요청 2026-09-04, 다른 봇의 카드 화면을 보고 "이런 식으로 나오는 거 아니야?"): 이미지 파일 주소만
  보내면 카톡이 카드를 안 만들어 주므로, `preview.js`가 og:image·og:title·og:description을 가진 작은 HTML을 `/p/emo/<키워드>`·
  `/p/chart/<이름>`·`/p/char/<닉네임>`(전투정보실 프로필 조회 → 칭호+닉네임 / 직업·서버·템렙)으로 내주고, 브리지 응답에 `link`를 실어
  폰 스크립트가 **카드 주소를 먼저, 본문을 이어서** 보낸다(`render.cardLinkFor`: 첨부 이모티콘/차트, 또는 캐릭터 이미지 썸네일 + 조회
  캐릭터). 카드가 나가면 본문의 이미지 URL 줄은 뺀다. 카드 하단에 서버 주소가 보이므로 도메인이 있으면 더 낫다(IP로 먼저 테스트).
  이모티콘 스위치 `KAKAO_EMOTICONS_ENABLED`(잠시 잠갔다가 카드 방식으로 다시 켬; false면 방 침묵·안내·이미지 서빙 404).
- **방에서는 침묵이 기본**: `/`로 시작하지 않고 (켜져 있을 때) 이모티콘 형식(`[키워드`)도 아니면 서버가 `{ text: null }` → 폰은 아무 말도 안 함.
  `/없는커맨드`는 안내문(1:1과 동일). 폰 스크립트도 같은 접두사 필터를 두어 잡담은 서버까지 오지 않는다.
- 입력 형식은 `/커맨드`만(사용자 결정 유지). 제외 커맨드는 `알림설정`만. **`/랭킹`·`/체급`은 `KAKAO_GUILD_ID`가 있을 때 허용**(사용자 요청
  2026-09-04 "랭킹 시스템도 넣고 싶은데 오픈챗봇에"): 서버 시작 시 그 디스코드 서버를 한 번 찾아 `KakaoInteraction.guild`에 넣어 주면
  기존 `runBoard`가 "그 서버에 /등록한 멤버"를 그대로 집계한다 — 디스코드에서 보는 판과 동일. **카톡에서 등록한 사람(`kakao:…`)도 같은
  판에 넣는다**(사용자 요청 2026-09-04 "카톡 등록한 사람도 랭킹에 넣어줘" — 처음엔 오픈프로필 외부인 유입을 우려해 뺐었다):
  `ranking.js`의 `registeredMembers()`가 서버 멤버인 디스코드 등록자 뒤에 `kakao:` 키 전부를 붙이고, 같은 캐릭터가 양쪽에 있으면 디스코드
  쪽만 남긴다. 디스코드 `/랭킹`에도 카톡 등록자가 함께 나온다. 외부인이 오픈프로필 1:1로 `/등록`하면 랭킹에 섞일 수 있다 — 알고 감수.
  `KAKAO_GUILD_ID`가 없으면 두 커맨드는 디스코드 전용 안내. 사용법 문구는 카카오에서 `/ㅂㅂㄱ …`처럼 슬래시 형태로 바꿔 보낸다(`usageForPrefix`).
- 평문 변환: `simpleText`들은 빈 줄로 이어 붙이고, `simpleImage`는 URL 한 줄(폰 봇은 이미지를 못 보냄 — 카톡이 링크 미리보기를 붙여 준다),
  `quickReplies`는 `▸ 이어서 쓸 수 있어요` 아래에 `· /군장 닉`처럼 한 줄씩. 커맨드별 카톡 전용 레이아웃은 `kakao/layout.js`
  (`❙ 제목` · `▸ 항목` · `└ 이어지는 줄` · `※ 주의` · `· 목록`)를 쓰고, 디스코드 임베드에는 손대지 않는다(커맨드 안에서 `platform === 'kakao'`로 갈림).
- **분량 규격은 채널마다 다르다**(`CHANNEL_LIMITS`). 오픈빌더 스킬은 카카오 규격 그대로 `simpleText` 1,000자 × outputs 3개이고 늘릴 수 없다.
  오픈채팅 브리지는 그 규격을 받지 않지만 방에 벽지 같은 메시지를 쏟지 않도록 **최종 메시지 1,500자**(`BRIDGE_TEXT_MAX`)로 끊는다.
  브리지 단계에서는 자르지 않고(`textMax: Infinity`) 모으기만 하고, 실제로 길이를 맞추는 곳은 `fitBridgeMessage()`다 —
  **본문 뒤에 붙는 후속 안내(`▸ 이어서 쓸 수 있어요` 블록)까지 합친 길이**로 계산하고, 안내는 잘리면 쓸모가 없으므로 자리를 먼저 빼 두고 본문만 줄인다.
  잘린 자리가 항목 한가운데면(`└`로 이어지는 줄이 날아갔으면) 머리줄도 같이 뺀다.
- **넘치는 분량은 전체 보기 페이지로**: 잘릴 때 본문 전문을 `kakao/result-store.js`에 담고 마지막 줄에
  `📄 뒤가 잘렸어요 · 전체 보기 <PUBLIC_BASE_URL>/p/full/<id>`를 붙인다. 보관은 **생성 후 30분**(최대 300건, 메모리에만 — 봇을 재시작하면
  기존 주소는 만료되고 커맨드를 다시 치면 새 주소가 나온다). 그래서 이 페이지만 `Cache-Control: no-store`로 내보낸다(카드 페이지는 5분 캐시 유지).
  랭킹처럼 목록이 긴 응답은 집계 수치·조회 실패 목록·기준 설명을 목록보다 **앞에** 두어 잘려도 주의사항이 방에 남게 한다.
  폰 스크립트는 그대로다 — 전체 보기 주소는 별도 `link`가 아니라 본문 마지막 줄이라 응답 형태(`{ text, link }`)가 바뀌지 않는다.
- 예산 25초 초과 시 `⏳ 조회에 시간이 걸려요…`가 방에 나가고 결과는 3분 보류 → 같은 커맨드를 다시 치면 즉시(1:1과 같은 메커니즘).
- **사람 식별**: 알림에는 닉네임만 있으므로 `kakao:oc:<닉네임>`을 사용자 키로 쓴다(방 이름은 넣지 않는다 — 방을 옮겨도 등록 유지).
  `/등록 캐릭명`은 그 닉네임에 묶인다. 닉네임을 바꾸면 다시 등록해야 하고, 같은 닉네임을 쓰는 다른 사람이 등록을 덮어쓸 수 있다 —
  한 길드 방이라 알고 감수(1:1 채널 봇 키는 별도).
- **등록 없이도 닉네임으로 조회**(사용자 결정 2026-09-04 "1번으로"): 브리지가 카톡 닉네임을 `userRequest.user.properties.nickname`으로
  넘기고 `KakaoInteraction`이 `user.username`에 넣어, `resolveCharacter`가 디스코드 서버 닉네임 폴백과 똑같이 동작한다 —
  등록이 없으면 카톡 닉네임을 캐릭터명으로 조회. 구분자(`/`·괄호 등)가 섞인 닉은 추측하지 않고 `/등록` 안내. 디스코드와의 "연동"은
  이 닉네임 = 캐릭터명 경로로 이뤄지며, 계정 자체를 잇는 연동 코드 방식은 필요해지면 추가.
- 봇 계정 자신의 메시지는 알림이 오지 않아 되돌이표가 생기지 않는다.

## 3. 운영 조건과 위험

- 필요: 24시간 전원·와이파이의 안드로이드 기기 1대(사용자 보유 확인), **봇 전용 카카오 계정**(전화번호 필요; 가상번호 계정은 정지 사례 많음),
  메신저봇R 설치 + 알림 접근 권한 + 카톡 알림 미리보기 켜기 + 배터리 최적화 제외, 봇 계정이 오픈채팅방에 참여(방 알림 켜기).
- 서버: 기존 `KAKAO_PORT`·`KAKAO_SKILL_SECRET`·`PUBLIC_BASE_URL` 그대로. OCI 보안 목록 TCP 80 인그레스는 여전히 필요(폰이 인터넷으로 접근).
- 위험: 카카오 약관 위반이라 **봇 계정이 정지될 수 있다**(본인 계정은 쓰지 않으므로 위험은 봇 계정에 한정). 카카오톡 앱 업데이트로 알림
  구조가 바뀌면 메신저봇R 패치까지 멈출 수 있다(9.7.5 사례). 폰이 꺼지거나 카톡이 백그라운드에서 죽으면 봇도 멈춘다.

## 4. 검증

- 스크래치 단위 테스트: `handleBridgeMessage` 침묵/응답/사용자 키, `flattenResponse` 이미지·이어서 줄, 서버 브리지 라우트(200·null·404).
- 실 API 직접 실행: `/정보 블레상돈`·`/체방`·`[따봉`·잡담·`/등록`을 브리지로 돌려 평문 확인.
- 폰 종단 확인은 배포 후 사용자 기기에서: 방에 `/도움말` → 답이 오면 끝.

## 5. 이후

- 배포(main 머지) → 폰 설정 → 방에서 확인 → 홈페이지 카카오 카드(사용법: `/커맨드`, 봇 계정 초대 안내)·README·v1.2 노트.
- 오픈빌더 스킬 엔드포인트는 남겨 둔다(나중에 채널 1:1도 열고 싶으면 그때 신청).
